# Krea 2 reference editing: project-managed ComfyUI

**Create from text** and **Krea reference edit** both use a project-managed ComfyUI subprocess so the mandatory Krea LoRA can run first. Reference edit uses image-grounded Krea2Edit nodes; Picture 1 is the source scene and Picture 2 is an optional person/object reference. The app also supports **Swap head / body** with Krea-specific BFS LoRAs through the same backend.

## Install once (Windows, Python 3.11)

1. From the project root, run `.\scripts\setup-comfy.ps1`. This clones ComfyUI and `lbouaraba/comfyui-krea2edit` into ignored `vendor/ComfyUI/` and installs ComfyUI's requirements in **the existing `.venv`**. Alternatively run `.\scripts\setup.ps1 -ComfyUI` for project and backend setup in one step. Review third-party source and license before installation.
2. Accept the gated Krea 2 Community License on Hugging Face and authenticate with `hf auth login` from `.venv` if requested. Run `.\scripts\download-models.ps1 -Preset krea-2` (or `.\.venv\Scripts\python.exe scripts\download_models.py --comfy-krea`). This downloads `Comfy-Org/Krea-2`'s Turbo FP8 diffusion checkpoint (~12.2 GiB), Qwen3-VL 4B FP8 encoder (~4.9 GiB), Qwen Image VAE, [the identity-edit LoRA](https://huggingface.co/conradlocke/krea2-identity-edit) `krea2_identity_edit_v1_2_r128.safetensors` (~0.85 GiB), and the mandatory 27 MB TextFusion adapter from `INFOMSG/Krea2_TextFusion` under the application filename `Krea2_ALWAYS_LOAD_FIRST.safetensors`. The preset also downloads the separate, optional official Krea Turbo LoRA into `models/loras/krea2/`; select that one in the UI only if wanted. Disk and download time are substantial; nothing is downloaded automatically by the UI.
3. If using Krea head/body swap, run `.\scripts\download-models.ps1 -BfsSwap` to obtain the matching BFS LoRAs under `models/loras/krea2/`. The backend adds that directory as a ComfyUI model search path; no duplicate copy is needed.
4. Launch `.\scripts\run.ps1 -ComfyUI`. When any Krea request arrives, the app starts `vendor/ComfyUI/main.py` from the current `.venv` on `127.0.0.1:8188` with low-VRAM and hosted-API nodes disabled. It stops only the subprocess it started when the app exits. ComfyUI startup logs are in `outputs/comfyui.log`.
5. Choose **Krea reference edit**. Only its **Picture 1 · source scene** and **Picture 2 · optional reference** upload controls appear; the three-image **Combine images** controls are hidden. Section **02 / Generation settings** identifies this dedicated Krea reference workflow without also showing the text-to-image model label. Enter an instruction and generate. For Krea head/body swaps choose **Swap head / body**, set the swap model to Krea and select Head or Body.

Run `python scripts/check_comfy_krea.py` once a request has started the backend to check installation, files, graph and server readiness. Before the first request, `comfyui` may say the server is unavailable because the backend starts on demand; with `PHOTO_EDIT_COMFY_AUTOSTART=true`, a stopped server alone does not fail the check. The bundled Krea API graph requires **no manual export**. Custom API-format JSON can still override the built-in graph via `PHOTO_EDIT_COMFY_REFERENCE_WORKFLOW`, `PHOTO_EDIT_COMFY_HEAD_WORKFLOW`, and `PHOTO_EDIT_COMFY_BODY_WORKFLOW`. A normal ComfyUI UI-format JSON cannot be submitted to its API.

## Controls and constraints

Every Krea workflow requires `vendor/ComfyUI/models/loras/Krea2_ALWAYS_LOAD_FIRST.safetensors`. The app fails before submitting a job if it is missing. In **Advanced · LoRAs**, set its dedicated **Krea2_ALWAYS_LOAD_FIRST · mandatory weight** slider (default 1.0; it cannot be 0). This adapter is inserted directly after the Krea model loader, **before every other LoRA**, including in **Create from text**, **Krea reference edit**, and Krea **Swap head / body**. Other selected Krea LoRAs also work in text mode and follow the mandatory adapter. Do not select this mandatory adapter again as an optional LoRA.

Text creation now uses the project-managed ComfyUI Krea graph so it can guarantee the mandatory adapter runs first; it no longer uses the Diffusers Krea text pipeline. The reference graph wires the source and optional second reference into `Krea2EditGroundedEncode` and `Krea2EditModelPatch`, then loads the identity-edit LoRA at weight 1.0. Selecting that **same** identity-edit file in a UI slot changes its existing weight; it does not load a second copy. Other selected Krea LoRAs are chained **after** it, in slot order, with their chosen weights. Krea head/body swaps instead load the BFS LoRA after the mandatory adapter at the BFS weight shown in the swap panel, followed by other selected Krea LoRAs. The bridge sets prompt, negative prompt, seed, steps, CFG and output resolution from Gradio. The default 1024-side/one-megapixel output budget still applies. The reference LoRA name can be overridden with `PHOTO_EDIT_COMFY_REFERENCE_LORA` if you have another compatible version.

**Create from text** shares the Combine images canvas controls: 1K or 2K at 1:1, 9:16, or 16:9. The ComfyUI text graph receives the selected width and height. The larger 2K budget applies only to the text and combine workflows; Krea reference editing and swaps retain their 1K cap. 2K may exceed the available VRAM on a 12 GB card.

Krea reference editing **does** use the Gradio LoRA slots: use Krea 2-compatible `.safetensors` files in `models/loras/krea2/`. The required identity-edit/BFS LoRA remains active. Weight 0 skips a slot without disabling the required base adapter. The source mask and edit-strength control do not apply to ComfyUI Krea editing; configure masking in a custom ComfyUI graph. First GPU load can take several minutes on a 12 GB card; adding adapters uses more VRAM/RAM. Keep one request at a time and close other GPU-heavy apps. ComfyUI writes uploaded references to its `input/` and results to its `output/` as well as the app's `outputs/`; remove those files separately if privacy requires it. The Krea 2 Community License requires appropriate content filtering or equivalent review. Use only images whose subjects have consented.

## Troubleshooting

- `scripts/setup-comfy.ps1` requires Git, Python 3.11 `.venv`, and a CUDA-enabled PyTorch build. If ComfyUI dependencies upgrade Torch or Transformers unexpectedly, rerun the main setup and verify both stacks with `python scripts/check_comfy_krea.py`.
- `scripts/download_models.py --comfy-krea` may require accepting model terms on the upstream Hub. It downloads approximately 18+ GiB; allow extra space for caches and existing Diffusers models.
- On startup failure inspect `outputs/comfyui.log`. A port conflict at 8188 is reported instead of silently reusing an unrelated service. `PHOTO_EDIT_COMFY_URL` must be a loopback HTTP URL. If the mandatory LoRA is missing, rerun `.\scripts\download-models.ps1 -Preset krea-2` to place it in `vendor/ComfyUI/models/loras/`.
- The existing FLUX `qwen3-4b-abl-q4_0.gguf` is **not** a Krea Qwen3-VL encoder. The Diffusers Krea snapshot under `models/repos/` does not replace ComfyUI's single-file checkpoints.
- Native ComfyUI Krea support or custom node APIs can change upstream. Pin and test a working checkout before upgrades. The bundled template is based on the upstream Krea2Edit v1.2 workflow; if node inputs change, update or override it with an API-format export.
